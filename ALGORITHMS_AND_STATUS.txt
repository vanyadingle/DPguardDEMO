1. РЕАЛИЗОВАННЫЕ АЛГОРИТМЫ
================================================================================

1.1 TELEMETRY AGGREGATION (network_telemetry.py)
------------------------------------------------
Raw records X = {ue_session_1, ..., ue_session_n}

Aggregations q(X) for slice eMBB-1:
  threat_level         = max(threat_score)
  active_connections   = count(sessions)
  anomaly_score        = mean(anomaly_flag) * 100
  failed_auth_attempts = sum(auth_failures)
  slice_load_percent   = f(total_bytes, capacity)
  packet_loss_rate     = g(anomaly_count, epoch)

Per-record adjacency -> L1 sensitivity bounds in metric catalog.


1.2 LAPLACE MECHANISM (telemetry_plane.py)
------------------------------------------
  M(X) = q(X) + eta,  eta ~ Laplace(Delta1(q) / epsilon)

Pure epsilon-DP for each metric release.


1.3 PRIVACY FILTER (privacy_accountant.py)
------------------------------------------
Before each query:
  if epsilon_request > epsilon_remaining -> PrivacyBudgetExceededError

Before plan execution:
  if sum(epsilon_plan) > epsilon_remaining -> reject plan

After successful release:
  epsilon_spent += epsilon


1.4 TYPED POLICY (privacy_policy.py)
------------------------------------
Pi : Role -> (authorized_metrics, authorized_actions, epsilon_bounds)

Checks:
  - metric in authorized_metrics(role)
  - min_epsilon <= epsilon <= max_epsilon
  - action in authorized_actions(role)


1.5 DP CONFIDENCE SET (admissibility_verifier.py)
-------------------------------------------------
For Laplace scale b = Delta1/epsilon:
  t_beta = b * ln(2/beta)
  B_beta(z_noisy) = [z_noisy - t_beta, z_noisy + t_beta]

Admissibility for permissive actions:
  Adm(a, z) iff upper_bound(threat) <= threshold
              AND upper_bound(anomaly) <= threshold
              AND upper_bound(auth_failures) <= 10
              AND upper_bound(packet_loss) <= 2%

Restrictive actions (block, isolate) always admissible.


1.6 ORCHESTRATION LOOP (orchestrator.py)
----------------------------------------
  1. Refresh raw aggregates (orchestrator never reads them)
  2. LLM.propose(intent, context, prior_dp_observations)
  3. Policy.validate(plan, action)
  4. Accountant.check_plan_budget(plan)
  5. For each query: accountant.check -> telemetry.release -> accountant.charge
  6. Verifier.verify(action, observations)
  7. ActionExecutor.execute(verified_action or safe_fallback)
  8. AuditLog.record_epoch(result)
  9. TelemetrySource.advance_epoch()


1.7 OPENAI LLM (openai_planner.py)
----------------------------------
  - System prompt with DP-Guard rules
  - User payload: intent, policy schema, network context, prior DP obs
  - Response format: JSON schema (strict)
  - Output: {reasoning, queries[], action_type, action_parameters}
