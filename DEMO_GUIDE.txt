ЧАСТЬ 3. ЧТО ПОКАЗЫВАТЬ В ВЫВОДЕ main.py
--------------------------------------------------------------------------------

При старте видно:
  - gNodeB ID и region (из data/network_slices.json)
  - 8 UE-сессий на slice eMBB-1
  - Raw aggregates (ПОМЕТИТЬ: LLM их НЕ видит!)
    threat_level: 71.00  <- высокая угроза
    active_connections: 8.00
    ...

ЭПОХА 1:
  [DP-READ] threat_level: z_noisy=...  <- зашумлённое значение
  [VERIFY] BLOCKED - allow_traffic заблокирован
  [ACTION] Safe fallback

ЭПОХА 2:
  Ещё DP-чтения (failed_auth_attempts, packet_loss_rate)
  Снова BLOCKED для allow_traffic

ЭПОХА 3:
  LLM предлагает block_traffic
  [VERIFY] ADMISSIBLE - restrictive action
  [ACTION] Executed: Blocked anomalous sessions

DEMO SUMMARY — итоговая таблица
Audit log: logs/audit.jsonl


--------------------------------------------------------------------------------
ЧАСТЬ 4. ПОКАЗ ФАЙЛОВ В IDE (порядок для преподавателя)
--------------------------------------------------------------------------------

1. data/ue_sessions.json
   "Вот реальные структурированные записи UE-сессий 6G-сети.
    Каждая запись: ue_id, slice, threat_score, auth_failures и т.д."

2. dp_guard/network_telemetry.py
   "Агрегирует raw records в KPI: max threat, count sessions, anomaly %."

3. dp_guard/telemetry_plane.py
   "Единственный доступ к raw data. Добавляет Laplace noise."

4. dp_guard/openai_planner.py
   "Реальный LLM через OpenAI. Получает только intent и schema, не raw data."

5. dp_guard/privacy_policy.py
   "Typed policy: какие метрики и действия разрешены для роли."

6. dp_guard/admissibility_verifier.py
   "Проверяет безопасность действий с учётом DP-шума."

7. dp_guard/orchestrator.py
   "Главный цикл: intent -> LLM -> budget -> DP reads -> verify -> execute."

8. logs/audit.jsonl
   "Полный аудит каждой эпохи для compliance."

--------------------------------------------------------------------------------
ЧАСТЬ 6. ГОТОВЫЙ ТЕКСТ ДЛЯ ЗАЩИТЫ (~2 мин)
--------------------------------------------------------------------------------

"Реализована полная версия DP-Guard — архитектуры LLM-оркестрации
 безопасности 6G-сетей с формальными гарантиями дифференциальной приватности.

 Система загружает реальные структурированные записи UE-сессий из JSON,
 агрегирует их в KPI и отдаёт LLM только DP-защищённые значения.

 Архитектура: 4 плоскости — Telemetry, Privacy Policy, Verification,
 Orchestration — плюс Action Executor и Audit Log.

 LLM реализован через OpenAI API с JSON schema output; без ключа работает
 mock-режим для offline демонстрации.

 В demo три эпохи: две блокировки allow_traffic verifier'ом из-за высокой
 угрозы (71 > порог 30), и финальное выполнение block_traffic.

 Все транскрипты записываются в logs/audit.jsonl.
 Unit-тесты покрывают DP mechanism, budget, policy и verifier."
