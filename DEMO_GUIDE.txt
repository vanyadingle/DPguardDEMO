ЧАСТЬ 2. ЗАПУСК ДЕМОНСТРАЦИИ
--------------------------------------------------------------------------------

ШАГ 2.1 — Запустить main.py
  • Убедитесь, что вы в папке DP_Guard и активировано (.venv)
  • Введите:

    python main.py

  • Нажмите: Enter

ШАГ 2.2 — Что должно появиться на экране
  Программа выполнит 3 эпохи (epochs) orchestration loop.
  Для каждой эпохи вы увидите блок:

  ============================================================
  EPOCH N | Intent: ...
  ============================================================

  Обратите внимание преподавателю на ключевые строки:

  [DP-READ] threat_level: z̃=... (ε=..., b=...)
    → Это зашумлённое значение метрики (Laplace mechanism).
    → LLM и orchestrator видят ТОЛЬКО z̃, не raw=45.

  [VERIFY] BLOCKED — Blocked 'allow_traffic': threat upper bound ...
    → Verification Plane заблокировал опасное действие LLM.

  [VERIFY] ADMISSIBLE — ...
    → Действие прошло проверку (для restrictive actions).

  [PRIVACY] Budget exhausted ...
    → Privacy Accountant не пустил запрос — бюджет исчерпан.

  [BUDGET] Spent ε=... / ε_tot=1.20 (remaining=...)
    → Текущее состояние privacy budget.

  В конце — таблица DEMO SUMMARY с итогами по эпохам.


--------------------------------------------------------------------------------
ЧАСТЬ 3. ЧТО ГОВОРИТЬ ПРЕПОДАВАТЕЛЮ (краткий сценарий ~5 мин)
--------------------------------------------------------------------------------

1. ПРОБЛЕМА
   "В zero-touch 6G LLM-оркестратор не должен видеть сырую телеметрию
    абонентов. DP-Guard решает это через typed DP interface."

2. ПОКАЗАТЬ ФАЙЛ telemetry_plane.py
   • В Cursor: File → Open Folder → C:\Users\IVAN\Projects\DP_Guard
   • Откройте: dp_guard\telemetry_plane.py
   • Покажите класс RawTelemetryStore с __raw_data (инкапсуляция)
   • Покажите метод release_metric: M(X) = q(X) + Laplace(Δ/ε)

3. ПОКАЗАТЬ privacy_accountant.py
   • Откройте: dp_guard\privacy_accountant.py
   • Объясните: check_budget() — privacy filter перед каждым запросом
   • PrivacyBudgetExceededError при превышении ε_tot

4. ПОКАЗАТЬ admissibility_verifier.py
   • Откройте: dp_guard\admissibility_verifier.py
   • Объясните: confidence interval B_β(z̃) для Laplace noise
   • allow_traffic блокируется, если upper bound threat > 30

5. ПОКАЗАТЬ orchestrator.py
   • Откройте: dp_guard\orchestrator.py
   • Покажите run_epoch(): plan → budget check → DP reads → verify → act

6. ЗАПУСТИТЬ python main.py (если ещё не запущено)
   • Эпоха 2: LLM предлагает allow_traffic, но verifier блокирует
     (истинный threat=45 скрыт, но верхняя граница CI > порога)
   • Эпоха 3: budget exhausted — privacy filter срабатывает

7. ЧТО ЕЩЁ НЕ РЕАЛИЗОВАНО
   "Это скелет: mock LLM, нет OpenAI API, нет (ε,δ)-Gaussian,
    Rényi composition, typed policy DSL — запланировано в следующих итерациях."

--------------------------------------------------------------------------------
ЧАСТЬ 6. УСТРАНЕНИЕ НЕПОЛАДОК
--------------------------------------------------------------------------------

Ошибка: "python is not recognized"
  → Установите Python 3.10+ с python.org, отметьте "Add to PATH"

Ошибка: "No module named numpy"
  → pip install -r requirements.txt (в активированном .venv)

Ошибка: эпоха 2 показывает ADMISSIBLE вместо BLOCKED
  → Это возможно из-за случайного шума (редко при seed=42)
  → Перезапустите: python main.py (seed фиксирован в main.py)

Ошибка: кодировка символов z̃ в консоли Windows
  → Не критично для демо; можно сказать "z-tilde — noisy DP value"
